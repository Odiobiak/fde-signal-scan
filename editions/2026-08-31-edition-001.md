## §01 Protocols and interop

### MCP spec 2026-07-28 removes sessions, session IDs, and the initialize handshake
**28 Jul 2026 · BREAKING · SHIPPED**
Protocol-level sessions and the `Mcp-Session-Id` header are gone, as is the `initialize` / `notifications/initialized` handshake. Requests self-describe through `_meta` keys. A new `server/discover` RPC, which servers MUST implement, advertises supported versions and capabilities. Servers needing cross-call state must mint explicit handles passed as ordinary tool arguments.
**Why it matters:** MCP servers behind a load balancer no longer need sticky sessions. But conversational agents that leaned on server-side session state need re-architecting, and the replacement handle carries an authorization burden it did not have before.
Source: https://modelcontextprotocol.io/specification/2026-07-28/changelog

### State handle hijacking: the footgun statelessness created
**28 Jul 2026 · SECURITY**
Official guidance replaces Session Hijacking with State Handle Hijacking. Servers MUST verify all inbound requests and MUST NOT treat possession of a state handle as authentication, and SHOULD bind handles server-side to the authenticated user, keying state as `<user_id>:<handle>` from the verified token rather than client input. New sections cover mix-up attacks, localhost redirect URI impersonation under CIMD, and SSRF against authorization servers.
**Why it matters:** Highest-value audit in the window. Teams will treat "remove sessions, pass a handle" as a transport chore. Done naively that refactor converts an authenticated session into an unauthenticated bearer-ish identifier: a trivially exploitable cross-tenant IDOR. Check the binding before the SDK upgrade lands.
Source: https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices

### Dynamic Client Registration deprecated in favour of CIMD
**28 Jul 2026 · BREAKING · DEPRECATION**
OAuth 2.0 DCR (RFC 7591) is deprecated, retained only for authorization servers lacking CIMD. Servers SHOULD emit the RFC 9207 `iss` parameter and clients MUST validate it before redeeming the code. Client credentials are bound to their issuing authorization server: key persisted credentials by issuer, never reuse across servers, re-register when the AS changes.
**Why it matters:** CIMD requires hosting a metadata document at a domain you control. New deployment artefact and new dependency for every client shipped into a customer environment, which makes it a procurement conversation, not just a code change.

### Transport: required routing headers, no SSE resumability, mandatory cache scoping
**28 Jul 2026 · BREAKING**
`Mcp-Method` and `Mcp-Name` headers now required on Streamable HTTP POSTs. The HTTP GET endpoint and `resources/subscribe` are replaced by a single `subscriptions/listen` stream. SSE resumability removed: a broken stream loses the in-flight request and clients MUST re-issue with a new request ID. List and read results require `ttlMs` and `cacheScope`.
**Why it matters:** Good — WAF and API gateway can enforce per-tool policy on headers alone. Bad — long-running tool calls over flaky corporate networks now fail hard instead of resuming, so idempotency moves into tool design. `cacheScope: "public"` on a tenant-varying tool list is a data-leak bug through any shared intermediary.

### Elicitation replaced by Multi Round-Trip Requests
**28 Jul 2026 · BREAKING**
MRTR replaces `roots/list`, `sampling/createMessage` and `elicitation/create`. Servers return `InputRequiredResult` with `inputRequests`; clients respond with `inputResponses` on a retry of the original request. All results carry a required `resultType`. `notifications/elicitation/complete` and `elicitationId` removed.
**Why it matters:** Lands directly on conversational agents. Any "I need one more field" flow becomes an idempotent retry rather than a callback, so tool handlers must tolerate repeated invocation with accumulating input.
Source: https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/mrtr

### Two in-window MCP CVEs
**18 & 27 Aug 2026 · SECURITY**
CVE-2026-75130: Context7 through 2.1.2 carries a prompt injection allowing malicious instructions to execute in connected coding agents via unsanitized Custom AI Instructions served through its MCP server, enabling credential exfiltration. NVD records CVSS v3.1 9.0 but v4.0 6.4. CVE-2026-81094: mcp-router before 0.6.3 bound its aggregator to all network interfaces by default and only enforced auth when explicitly configured.
**Why it matters:** Context7 is the cleanest argument that MCP tool *results* are untrusted data. Know the 9.0 vs 6.4 divergence before a customer security team quotes one number. The mcp-router pattern is what to check for in any MCP proxy in a customer network, since the aggregator holds the union of every downstream credential.

### MCP roadmap signals progressive tool discovery and DPoP
**22 Aug 2026 · PROPOSED, not shipped**
Five working groups: agentic messaging primitives, HTTP transport unification replacing stdio, agent identity via DPoP and Workload Identity Federation, improved primitives including progressive discovery for large tool catalogs, and SDK conformance.
**Why it matters:** Progressive discovery is the admission that 200 tools in one `tools/list` does not scale. If you are hitting that today, expect a standard answer within ~2 revisions rather than over-engineering a private workaround.

### CORRECTION to carry into meetings
A2A shipped **nothing** between 25 Jul and 31 Aug 2026. Last releases were v1.0.0 (March) and v1.0.1 (May). The Linux Foundation "150+ organizations" milestone is dated 9 April 2026 and is routinely mis-quoted as recent. "WebMCP is an official W3C standard" could not be confirmed from any primary source.

## §02 Voice and speech models

### Flux TTS goes GA and quietly replaces Aura as the Voice Agent default
**Deepgram · 12 Aug 2026 · GA · SILENT DEFAULT CHANGE**
Model IDs `flux-{voice}-{language}`, 36 English voices across 7 accents, English only at launch. Deepgram states responses begin in as low as 80 ms, billing per synthesized character, with an `Interrupt` operation returning `text_spoken` and `text_remaining`. Omitting `agent.speak` now yields `flux-kit-en`.
**Why it matters:** Any Voice Gateway or Deepgram config that relied on Aura *by omission* now speaks in a different voice. `Interrupt` playback-offset is useful for barge-in bookkeeping. Unresolved: 8 kHz μ-law/A-law telephony output, and the concurrency ceiling (45 streaming connections pay-as-you-go NA, 5 in EU/AU) which blocks load tests.
Source: https://deepgram.com/learn/flux-tts-what-ships-at-ga

### Turn-taking control: ForceEndTurn and eot_threshold
**Deepgram · 26 & 28 Aug 2026 · SHIPPED**
Three modes: automatic, semi-manual with `{"type":"ForceEndTurn"}`, and fully manual where `eot_threshold=1.0` suppresses native detection. Threshold changeable mid-stream via `Configure` without reconnecting. `EndOfTurn` events carry a `trigger` field valued `model`, `manual` or `timeout`. Backward compatible.
**Why it matters:** Most operationally useful item in the window. Endpointing is where PSTN deployments fail: DTMF entry, push-to-talk, IVR handoffs, long alphanumeric account numbers. Forcing turn-end on a DTMF signal removes the entire "agent interrupts the caller mid-account-number" defect class.
Source: https://developers.deepgram.com/changelog/2026/8/28

### Mid-session language switching, per-turn STT latency, 2-hour session cap
**Deepgram · 31 Jul 2026 · SHIPPED · NEW FAILURE MODE**
`UpdateListen` switches STT model and language mid-session without restarting. `LatencyReport` gained `stt_latency`, completing the STT→LLM→TTS breakdown. Sessions auto-close after 2 hours with a warning at 1h55m; `KeepAlive` cannot extend it.
**Why it matters:** Language switching answers multilingual routing without tearing down the media session. Per-turn `stt_latency` is what you need to defend a latency SLA. The 2-hour cap is new: audit long-hold, warm-transfer and agent-assist scenarios.

### GPT-Transcribe and GPT-Live-Transcribe ship; whisper-1 family gets a shutdown date
**OpenAI · 28 Jul 2026 · SHIPPED · DEADLINE**
Both accept free-form transcription context, keyword hints, prior dialogue and multiple expected input languages. Reported: 19.70% vs 20.33% error rate on Common Voice across 22 languages; 9.60% vs 11.65% on a real-world benchmark across nine languages. The 26 Aug changelog sets the whisper-1 / gpt-4o-transcribe family shutdown at 26 Feb 2027.
**Why it matters:** Keyword hints plus free-form context is the practical fix for mistranscribed product names, policy numbers and agent names. Pricing, per-model latency and the full language list are not stated.

### Gemini 3.5 Transcribe and Transcribe Live go GA, with a 10-minute streaming ceiling
**Google · 26 Aug 2026 · GA**
Non-streaming high-accuracy model with utterance-based language detection across 85+ languages, plus low-latency bidirectional streaming over WebSockets. File mode: word-level timestamps, diarization up to 8 speakers, custom vocabulary biasing up to 1,000 terms. Live streaming supports biasing and smart formatting but not timestamps or diarization, capped at 10 minutes per session.
**Why it matters:** Strong on paper for SKU-heavy enterprise vocabularies and mid-session code-switching. But the 10-minute live cap rules it out for most contact-centre calls without reconnect-and-stitch logic, and no streaming diarization rules out real-time agent-assist on merged audio. Worth knowing, not worth proposing yet.

### Sonic-3.6: 44 languages, 61 locales, pinnable dated model IDs
**Cartesia · 27 Aug 2026 · GA**
Pinnable as `sonic-3.6-2026-08-27`, Odia and Urdu added, 500+ preset voices, Hindi-English code-switching. Vendor claims replies under 90 ms, nearly 2x faster generation than v3 Conversational, 99.9% uptime SLA, top Artificial Analysis leaderboard placement. Existing clones carry over. Sonic-2 and Sonic-turbo sunset after 20 Oct 2026.
**Why it matters:** Best language-coverage-per-latency story in the window for multilingual EMEA voice. Pinnable dated ID is the right production pattern. Not auto-default, so no surprise voice change but no free upgrade either. Preference claims are vendor-run.

### Two tuning knobs and one default migration
**ElevenLabs · AssemblyAI · Aug 2026 · SHIPPED**
ElevenLabs shipped no new TTS or STT model. It did ship Scribe v2 Realtime entity detection emitting `committed_transcript_entities`, and `merge_with_default_ignore_terms` for interruption terms. AssemblyAI shipped tool-parameter guardrails reporting hallucinated arguments dropping 2.5% to 0%, and fixed a Playground bug that silently disabled adaptive turn detection.
**Why it matters:** Realtime entity detection gives structured PII extraction at the ASR layer before NLU sees it, useful for redaction and slot-filling. `merge_with_default_ignore_terms` lets you add domain filler terms that should *not* count as an interruption.

### OPEN QUESTION across every new TTS model
8 kHz μ-law and A-law telephony output is unconfirmed for Flux TTS, Sonic-3.6 and Gemini Transcribe Live. No primary announcement addressed it. For Voice Gateway work this is the highest-value follow-up in the scan and must be verified against API reference docs, not blog posts. No pricing published for Gemini 3.5 Transcribe, GPT-Transcribe or Sonic-3.6 either.

## §04 Frameworks, eval and observability

### OpenAI Agents SDK: silent default model change, and guardrail-blocked output was leaking into persisted state
**11 & 19 Aug 2026 · BREAKING · SECURITY FIX**
v0.20.0 made `gpt-5.6-luna` the implicit default and migrated MCP dependencies, requiring apps with custom MCP HTTP auth to pin `mcp<2` or adopt v2 types. v0.22.0 rejects conflicting provider options when `OpenAIProvider` receives an explicit client, and redacts terminal function-tool output rejected by output guardrails from replayable and persisted SDK state.
**Why it matters:** The silent default-model change is the classic landmine: an unpinned deployment changes model, cost and behaviour on a `pip install`. Mandate explicit pinning in every client repo. The redaction is more serious: previously, tool output a guardrail *blocked* could still land in persisted state, recoverable from checkpoints and traces. If a client runs output guardrails as a compliance control on an older SDK, that control was leaking into durable storage. Audit what your checkpointer persists, in any framework.

### Langfuse v4 restructures storage; Cloud v3 ends 16 November
**17 Aug 2026 · BREAKING · DEADLINE**
One denormalized observations table replaces v3's read-time joins, append-only, removing query-time deduplication, claiming at least 10x faster dashboards on large projects. New: Monitors with threshold notifications, deterministic code evaluators, full-text search, Observations and Metrics API v2. Minimum SDKs Python 4.7.0 and JS/TS 5.4.0.
**Why it matters:** Hard-dated migration on the observability layer, always the last thing budgeted. Clients on Cloud v3 have ~11 weeks. API v1→v2 breaks custom dashboards and compliance exports. Self-hosted sits on unpatched software after January 2027.

### The eval layer converged on sessions, and two silent-telemetry bugs got fixed
**Aug 2026 · SHIPPED**
LangSmith expanded annotation queues to thread items with bulk operations. Braintrust shipped trace groups so a dataset row references a group of traces, plus group-scoped online scoring. CrewAI promoted conversational flows to stable and fixed task failures being recorded as successes. LangSmith fixed custom code evaluators that timed out silently rather than recording errors.
**Why it matters:** Three independent vendors moving the same direction in two weeks signals that per-turn evaluation is now considered inadequate for agents. If a client's eval strategy still scores individual LLM calls, it is behind the tooling. The bug fixes are sharper: any client reporting CrewAI success rates before 27 Aug was reading inflated numbers, and any eval suite on an older LangSmith build may have shown green while evaluators timed out.

### Microsoft Agent Framework channels, plus a citable security position
**26 & 27 Aug 2026 · SHIPPED**
Five hosting packages expose an agent or workflow over OpenAI Responses, Telegram, A2A and MCP, with the framework handling protocol conversion while the application retains routing, authn and authz. A companion production-readiness post states plainly that giving the model arbitrary read/write access to the container filesystem, or letting it run shell commands, is a serious security risk.
**Why it matters:** "One governed agent, many front doors" is a real lever for clients wanting one agent reachable from Teams, a contact-centre channel and other agents. Caveat: A2A and MCP hosting turn an internal agent into a network-reachable endpoint and Microsoft explicitly leaves auth to you. The security post is the more useful artefact: a named vendor on record that agent shell access is a serious risk is the citation you want when pushing back on a client or competing integrator proposing it "for flexibility."

### LangGraph shipped patches only; 1.4.0 alphas appeared end of August
**Jul–Aug 2026 · QUIET**
langgraph 1.2.10 and 1.2.11, langchain 1.3.15 through 1.3.18, no breaking changes documented. Substantive: `trace_policy` on `add_node`, a checkpoint fix collecting writes at plain-value seed in delta channel history, `langgraph-checkpoint` 4.2.0 and `langgraph-checkpoint-postgres` 3.1.2. langchain 1.4.0a1/a2 appeared 27–28 Aug.
**Why it matters:** Good news for a client: the framework most enterprise agent builds sit on had a quiet six weeks while OpenAI and Langfuse moved underneath. On Postgres persistence, checkpoint 4.2.0 carries a delta-channel history fix affecting replay correctness. Watch 1.4.0: alphas at end of August means a minor with possible migration work in September or October.

### BLIND SPOT: portable agent telemetry is in limbo
All `gen_ai.*` attributes were deprecated out of the main OpenTelemetry semantic conventions repo in June 2026 and moved to a dedicated GenAI repo, which has shipped zero releases since. Pydantic AI v2 moved to its own instrumentation version 5 naming, and Microsoft's harness guidance assumes OTel export. Any client betting on vendor-neutral portable agent telemetry is betting on a spec in limbo. Design the collector layer so attribute renaming is a config change, not a rewrite.

## §06 Method and known limits

- Primary sources only where possible. Every item links a vendor changelog, release note, spec page or CVE record. Where only secondary reporting existed, the item says so.
- SHIPPED is separated from ANNOUNCED/PROPOSED. This distinction is the biggest source of confident-sounding errors in AI news.
- Vendor benchmark claims are reproduced, not endorsed. Cartesia's leaderboard placement, AssemblyAI's 2.5%→0%, Deepgram's 80 ms, and NiCE's customer figures are all vendor- or customer-reported on unspecified test sets.
- Unconfirmed is written as unconfirmed. Absence of a finding is not evidence of absence.
- Item count is not market signal. Deepgram dominates §02 partly because it publishes a granular dated changelog and its competitors do not.
- Fetched pages are treated as data, never instructions. Deepgram, ElevenLabs and modelcontextprotocol.io documentation prepend directive text addressed to AI readers. It is benign and first-party, and was ignored. Nothing malicious was encountered.
