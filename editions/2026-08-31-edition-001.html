§01

Protocols and interop

the big one this window

MCP shipped its largest breaking revision to date. A2A had no spec activity in the window at all, despite how often it is described as moving fast.

Model Context Protocol28 Jul 2026BreakingShipped

Spec 2026-07-28 removes sessions, session IDs, and the initialize handshake

Protocol-level sessions and the Mcp-Session-Id header are gone, as is the initialize / notifications/initialized handshake. Every request now self-describes through _meta keys. A new server/discover RPC, which servers MUST implement, advertises supported versions and capabilities. Servers that need cross-call state must mint explicit handles passed as ordinary tool arguments.

Why it mattersAny MCP server behind a load balancer no longer needs sticky sessions, which is a genuine operational win. But conversational agents that leaned on server-side session state need re-architecting, and the handle you replace the session with now carries an authorization burden it did not have before. See the next item before you ship that refactor.

source · modelcontextprotocol.io/specification/2026-07-28/changelog

Model Context Protocol28 Jul 2026Security

State handle hijacking: the new footgun statelessness created

The official security guidance replaces its Session Hijacking section with State Handle Hijacking. Servers MUST verify all inbound requests and MUST NOT treat possession of a state handle as authentication, and SHOULD bind handles server-side to the authenticated user, keying state as <user_id>:<handle> from the verified token rather than from client input. New sections also cover mix-up attacks, localhost redirect URI impersonation under CIMD, and SSRF against authorization servers.

Why it mattersThis is the highest-value audit in the window. Teams will treat "remove sessions, pass a handle instead" as a transport chore and ship it. Done naively, that refactor silently converts an authenticated session into an unauthenticated bearer-ish identifier, which is a trivially exploitable cross-tenant IDOR. Check the binding before the SDK upgrade lands, not after.

source · modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices

Model Context Protocol28 Jul 2026BreakingDeprecation

Dynamic Client Registration deprecated in favour of Client ID Metadata Documents

OAuth 2.0 DCR (RFC 7591) is deprecated, retained only for authorization servers that lack CIMD. Authorization servers SHOULD emit the RFC 9207 iss parameter and clients MUST validate it before redeeming the code. Client credentials are now explicitly bound to their issuing authorization server: clients MUST key persisted credentials by issuer, MUST NOT reuse them across servers, and MUST re-register when the AS changes.

Why it mattersCIMD requires hosting a metadata document at a domain you control. That is a new deployment artefact and a new dependency for every client you ship into a customer environment, which makes it a procurement and hosting conversation, not just a code change. Start it early.

source · modelcontextprotocol.io/specification/2026-07-28/changelog

Model Context Protocol28 Jul 2026Breaking

Transport: required routing headers, no SSE resumability, mandatory cache scoping

Mcp-Method and Mcp-Name headers are now required on Streamable HTTP POSTs. The HTTP GET endpoint and resources/subscribe are replaced by a single subscriptions/listen stream. SSE resumability is removed entirely: a broken response stream loses the in-flight request and clients MUST re-issue it with a new request ID. List and read results now require ttlMs and cacheScope.

Why it mattersTwo opposite consequences. Good: your WAF and API gateway can enforce per-tool policy on headers alone without parsing JSON, which is a real enterprise win worth designing for. Bad: long-running tool calls over flaky corporate networks now fail hard instead of resuming, so idempotency has to move into your tool design. And cacheScope: "public" on a tool list that varies by tenant is a data-leak bug through any shared intermediary.

source · modelcontextprotocol.io/specification/2026-07-28/changelog

Model Context Protocol28 Jul 2026Breaking

Elicitation is dead; Multi Round-Trip Requests replace server-initiated calls

MRTR replaces roots/list, sampling/createMessage and elicitation/create. Servers return an InputRequiredResult with an inputRequests field; clients respond with inputResponses on a retry of the original request. All results now carry a required resultType. The notifications/elicitation/complete notification and elicitationId are removed.

Why it mattersThis lands directly on conversational agents. Any "I need one more field from the user" flow must be rewritten as an idempotent retry rather than a callback, meaning your tool handlers have to tolerate repeated invocation with accumulating input. A server correlating an elicitation across retries now has to encode its own identifier in requestState.

source · modelcontextprotocol.io/specification/2026-07-28/basic/patterns/mrtr

CVE-2026-75130 / CVE-2026-8109418 & 27 Aug 2026Security

Two in-window MCP CVEs: prompt injection in Context7, open-by-default binding in mcp-router

Context7 through 2.1.2 carries a prompt injection allowing malicious instructions to execute in connected coding agents via unsanitized Custom AI Instructions served through its MCP server, enabling credential exfiltration and destructive file operations. NVD records CVSS v3.1 9.0 but CVSS v4.0 6.4. Separately, mcp-router before 0.6.3 bound its aggregator to all network interfaces by default and only enforced authentication when an operator explicitly configured it.

Why it mattersContext7 is the cleanest available argument for the rule that MCP tool results are untrusted data. Know the 9.0 versus 6.4 score divergence before a customer security team quotes one number at you. The mcp-router pattern is the one to check for in any MCP proxy deployed into a customer network, because the aggregator holds the union of every downstream credential.

sources · nvd.nist.gov/vuln/detail/CVE-2026-75130  ·  ionix.io/threat-center/cve-2026-81094

Model Context Protocol22 Aug 2026Proposed

Roadmap signals progressive tool discovery and DPoP-based workload identity

Five working-group areas: agentic messaging primitives via webhooks and channels, HTTP transport unification to replace stdio, agent identity and security through DPoP and Workload Identity Federation, improved primitives including standardized tool result contracts and progressive discovery for large tool catalogs, and SDK conformance. None of this is in a specification yet.

Why it mattersTwo things to plan around. Progressive discovery is the admission that dumping 200 enterprise tools into one tools/list does not scale, so if you are hitting that today expect a standard answer within roughly two revisions and avoid over-engineering a private workaround. DPoP and WIF are the answer to the service-to-service auth question large customers keep asking, without long-lived bearer tokens.

source · blog.modelcontextprotocol.io/posts/mcp-roadmap

Correction worth carrying into meetings A2A shipped nothing between 25 July and 31 August 2026. The last releases were v1.0.0 in March and v1.0.1 in May. The widely-cited Linux Foundation "150+ organizations" milestone is dated 9 April 2026 and is regularly mis-quoted as recent. Similarly, "WebMCP is an official W3C standard" could not be confirmed from any primary source. If a competitor or a customer leads with A2A momentum, the dates are on your side.
§02

Voice and speech models

the layer your calls run on

A heavy window. Note the sampling bias before reading anything into item counts: Deepgram publishes a dated, granular changelog and most competitors do not.

Deepgram12 Aug 2026GASilent default change

Flux TTS goes GA and quietly replaces Aura as the Voice Agent default

Model IDs take the form flux-{voice}-{language}, with 36 English voices across 7 accents, English only at launch. Deepgram states it begins responding in as low as 80 ms, bills per synthesized character, and exposes an Interrupt operation returning text_spoken and text_remaining. Omitting agent.speak now yields flux-kit-en rather than an Aura voice.

Why it mattersAny Voice Gateway or Deepgram agent config that relied on Aura by omission now speaks in a different voice. That is a brand defect a customer notices before you do. The Interrupt playback-offset response is genuinely useful for barge-in bookkeeping, since it tells you exactly what the caller heard before cutting in. Two open questions the GA post does not answer: 8 kHz μ-law and A-law telephony output, and the concurrency ceiling (45 streaming connections on pay-as-you-go NA, 5 in EU and AU) which is a hard blocker for load tests.

source · deepgram.com/learn/flux-tts-what-ships-at-ga

Deepgram26 & 28 Aug 2026Shipped

Turn-taking finally gets manual control: ForceEndTurn and eot_threshold

Flux now supports three turn-taking modes: automatic detection, semi-manual with a {"type":"ForceEndTurn"} override, and fully manual where eot_threshold=1.0 suppresses native detection entirely. The threshold can change mid-stream via a Configure message without reconnecting, and EndOfTurn events now carry a trigger field valued model, manual or timeout. Backward compatible.

Why it mattersThe most operationally useful item in the window. Endpointing is where PSTN deployments actually fail: DTMF entry, push-to-talk, IVR handoffs, long alphanumeric account numbers. Being able to force turn-end on a DTMF signal or suppress model endpointing per turn removes the entire "agent interrupts the caller mid-account-number" defect class. The trigger field also gives you clean attribution for turn-boundary errors in call analytics.

source · developers.deepgram.com/changelog/2026/8/28

Deepgram31 Jul 2026ShippedNew failure mode

Mid-session language switching, per-turn STT latency, and a 2-hour session cap

UpdateListen now switches STT model and language mid-session without restarting. LatencyReport gained stt_latency, completing the STT to LLM to TTS breakdown per turn. Voice Agent sessions now auto-close after 2 hours, with a warning at 1h55m; KeepAlive cannot extend it.

Why it mattersMid-session language switching is the clean answer to multilingual routing without tearing down the media session, which matters for any EU or DACH deployment where the caller switches language after the IVR. Per-turn stt_latency is exactly what you need to defend a latency SLA and prove whether ASR, the LLM or TTS is the culprit. The 2-hour cap is a new failure mode: audit long-hold, warm-transfer and agent-assist scenarios, and handle the 1h55m warning explicitly.

source · developers.deepgram.com/changelog/2026/7/31

OpenAI28 Jul 2026ShippedDeadline

GPT-Transcribe and GPT-Live-Transcribe ship; the whisper-1 family gets a shutdown date

Both accept free-form transcription context, keyword hints, prior dialogue and multiple expected input languages. Reported figures: 19.70% error rate versus 20.33% on Common Voice across 22 languages, and 9.60% versus 11.65% on a real-world benchmark across nine languages. The 26 August changelog sets the shutdown of whisper-1 and the gpt-4o-transcribe family at 26 February 2027.

Why it mattersKeyword hints plus free-form context is the practical fix for the perennial enterprise problem of product names, policy numbers and agent names being mistranscribed. But the deprecation is the action item: every Cognigy deployment or PoC pinned to that family has a hard deadline. Pricing, per-model latency and the full language list are not stated in the announcement.

source · developers.openai.com/api/docs/changelog

Google26 Aug 2026GA

Gemini 3.5 Transcribe and Transcribe Live go GA, with a 10-minute streaming ceiling

Two dedicated STT models: a non-streaming high-accuracy model with utterance-based language detection across 85+ languages, and a low-latency bidirectional streaming model over WebSockets. File mode supports word-level timestamps, diarization up to 8 speakers, and custom vocabulary biasing up to 1,000 terms. Live streaming supports biasing and smart formatting but not timestamps or diarization, and is capped at 10 minutes per session.

Why it mattersStrong on paper for product-name and SKU-heavy enterprise vocabularies, and mid-session code-switching across 85+ languages is a real differentiator. But the 10-minute live session limit rules it out for most contact-centre calls without reconnect-and-stitch logic that risks losing context at the seam, and no streaming diarization rules it out for real-time agent-assist on merged audio. Worth knowing, not worth proposing yet.

source · ai.google.dev/gemini-api/docs/models/gemini-3.5-transcribe

Cartesia27 Aug 2026GA

Sonic-3.6: 44 languages, 61 locales, pinnable dated model IDs

Pinnable as sonic-3.6-2026-08-27, with Odia and Urdu added, 500+ preset voices, and Hindi-English code-switching. Cartesia claims replies under 90 ms, generation nearly 2x faster than v3 Conversational, a 99.9% uptime SLA, and top placement on the Artificial Analysis speech leaderboard. Existing voice clones carry over. Sonic-2 and Sonic-turbo sunset after 20 October 2026.

Why it mattersBest language-coverage-per-latency story in the window for multilingual EMEA voice work, and the pinnable dated ID is the right pattern for production stability. Unlike Flux it is not auto-default, so traffic must be repointed manually: no surprise voice change, but no free upgrade either. Preference-test claims are vendor-run; treat them as marketing, not procurement evidence. Telephony codec support is unconfirmed.

source · cartesia.ai/blog/sonic-3.6

ElevenLabs · AssemblyAIAug 2026Shipped

Two tuning knobs worth knowing, and one default migration to pin against

ElevenLabs shipped no new TTS or STT model this window. It did ship Scribe v2 Realtime entity detection emitting committed_transcript_entities, and merge_with_default_ignore_terms for interruption terms. AssemblyAI shipped tool-parameter guardrails for Voice Agent tool calls, reporting hallucinated arguments dropping from 2.5% to 0%, and fixed a Playground bug that had silently disabled adaptive turn detection.

Why it mattersRealtime entity detection means structured PII extraction at the ASR layer, before your NLU sees it, which is useful for both redaction and slot-filling. merge_with_default_ignore_terms is a barge-in knob letting you add domain filler terms that should not count as an interruption. AssemblyAI's guardrail targets the top failure mode in voice-driven API calls (wrong account, wrong date), though the 2.5% to 0% figure is self-reported on an unspecified test set.

sources · elevenlabs.io/docs/changelog  ·  assemblyai.com/changelog

Open question across every new TTS model this window 8 kHz μ-law and A-law telephony output is unconfirmed for Flux TTS, Sonic-3.6 and Gemini Transcribe Live. None of the primary announcements addressed it. For Voice Gateway work this is the highest-value follow-up in the whole scan, and it has to be verified against API reference docs rather than blog posts. No pricing figures were published for Gemini 3.5 Transcribe, GPT-Transcribe or Sonic-3.6 either.

Cognigy and the CCaaS field

your platform and your competitors

The most commercially significant item in the entire scan is in this section, and it is not a feature.

Cognigy 2026.164 Aug 2026GA

NiCE CXone handover providers exit beta; Context object jumps 65 kB to 256 kB

The beta designation is removed from the NiCE CXone handover providers. The Context object limit expands fourfold, the Snapshot and Package upload limit rises to 8 GB, endpoint auth standardises on the x-cognigy-endpoint-key header, and Genesys Cloud Open Messaging handover gains real-time queue notifications with live estimated wait time. Voice Gateway adds Deepgram region selection and a Model Improvement Program opt-in.

Why it mattersCXone handover going GA removes the "it's still beta" objection from every CXone plus Cognigy deal, which is worth more than any feature this window. Two watch-outs: the x-cognigy-endpoint-key standardisation is a breaking risk for customer integrations still sending legacy auth headers, and the Deepgram Model Improvement Program opt-in trades call audio for training in exchange for reduced cost. Confirm every regulated customer is explicitly opted out and that it is documented, because that is exactly the setting that surfaces in a security review after the fact.

§04

Frameworks, eval and observability

what you build on and prove with

One convergence worth noticing: three independent eval vendors moved from scoring single calls to scoring whole sessions within two weeks of each other.

OpenAI Agents SDK11 & 19 Aug 2026BreakingSecurity fix

Default model changes silently in v0.20.0; guardrail-blocked output was leaking into persisted state

v0.20.0 made gpt-5.6-luna the implicit default model and migrated MCP dependencies, requiring apps with custom MCP HTTP auth to pin mcp<2 or adopt v2 types. v0.22.0 rejects conflicting provider options when OpenAIProvider receives an explicit client, and redacts terminal function-tool output rejected by output guardrails from replayable and persisted SDK state.

Why it mattersThe silent default-model change is the classic enterprise landmine: an unpinned client deployment changes model, cost and behaviour on a pip install. Mandate explicit model pinning in every client repo. The guardrail redaction is the more serious story: previously, tool output a guardrail blocked could still land in persisted state, meaning the blocked content was recoverable from checkpoints and traces. If a client runs output guardrails as a compliance control on an older SDK, that control was leaking into durable storage. Audit what your checkpointer persists, in any framework.

source · github.com/openai/openai-agents-python/releases/tag/v0.22.0

Langfuse17 Aug 2026BreakingDeadline

Langfuse v4 restructures storage; Cloud v3 support ends 16 November

One denormalized observations table replaces v3's read-time joins, in an append-only design removing query-time deduplication, with claims of at least 10x faster dashboards on large projects. New: Monitors with threshold notifications, deterministic code evaluators, full-text search, and Observations and Metrics API v2. Minimum SDKs are Python 4.7.0 and JS/TS 5.4.0. Self-hosted has no forced cutover but v3 security patches end January 2027.

Why it mattersA hard-dated migration on the observability layer, which is always the last thing anyone budgets for. Clients on Langfuse Cloud v3 have roughly eleven weeks from the release. The API v1 to v2 change breaks any custom dashboard or compliance export built on the old schema. Self-hosted clients get a longer runway and then sit on unpatched software after January 2027, which belongs in a risk register now rather than at renewal.

source · langfuse.com/changelog/2026-08-17-langfuse-v4

LangChain · Braintrust · CrewAIAug 2026Shipped

The eval layer converged on sessions, and two silent-telemetry bugs got fixed

LangSmith expanded annotation queues to thread items with bulk operations. Braintrust shipped trace groups so a dataset row references a group of traces rather than one, plus group-scoped online scoring. CrewAI promoted conversational flows to stable and fixed task failures being recorded as successes. LangSmith also fixed custom code evaluators that timed out silently rather than recording errors.

Why it mattersThree independent vendors moving the same direction in two weeks is a strong signal that per-turn evaluation is now considered inadequate for agents. If a client's eval strategy still scores individual LLM calls, it is behind the tooling. The two bug fixes are the sharper item: any client reporting CrewAI success rates before 27 August was reading inflated numbers, and any eval suite on an older LangSmith build may have shown green while evaluators timed out. Both undermine every reliability claim built on that telemetry.

sources · docs.langchain.com/langsmith/changelog  ·  braintrust.dev/docs/reference/changelog  ·  docs.crewai.com/en/changelog

Microsoft26 & 27 Aug 2026Shipped

Agent Framework channels expose one agent as MCP server and A2A peer; plus a citable security position

Five hosting packages expose an agent or workflow over OpenAI Responses, Telegram, A2A and MCP, with the framework handling protocol conversion at the boundary while the application retains routing, authentication and authorization. A companion post on production readiness states plainly that giving the model arbitrary read/write access to the container filesystem, or letting it run shell commands, is a serious security risk, and recommends routing file operations through external storage abstractions.

Why it matters"One governed agent, many front doors" is a real architectural lever for clients who want one agent reachable from Teams, a contact-centre channel and other agents without three implementations. The caveat is that A2A and MCP hosting turn an internal agent into a network-reachable endpoint and Microsoft explicitly leaves authn/authz to you. The security post is the more immediately useful artefact: a named vendor stating on record that agent shell access is a serious risk is exactly the citation you want when pushing back on a client or a competing integrator proposing it "for flexibility."

source · devblogs.microsoft.com/agent-framework/agent-harness-making-your-claw-production-ready

LangGraphJul–Aug 2026Quiet

LangGraph shipped patches only, and 1.4.0 alphas appeared at end of August

langgraph 1.2.10 and 1.2.11, langchain 1.3.15 through 1.3.18, with no breaking changes documented. Substantive items: trace_policy exposed on add_node, a checkpoint fix collecting writes at plain-value seed in delta channel history, and releases of langgraph-checkpoint 4.2.0 and langgraph-checkpoint-postgres 3.1.2. langchain 1.4.0a1 and a2 appeared 27 to 28 August.

Why it mattersGood news to put in front of a client: the framework most enterprise agent builds sit on had a quiet, stability-focused six weeks precisely while OpenAI and Langfuse were moving underneath. If you run Postgres persistence, checkpoint 4.2.0 carries a delta-channel history fix affecting replay correctness. Watch 1.4.0: alphas at end of August means a minor with possible migration work is likely in September or October, so do not let a client start a long build on 1.3.x without a version policy.

source · docs.langchain.com/oss/python/releases/changelog

Blind spot: portable agent telemetry is in limbo All gen_ai.* attributes were deprecated out of the main OpenTelemetry semantic conventions repo in June 2026 and moved to a dedicated GenAI repo, which has shipped zero releases since. Meanwhile Pydantic AI v2 moved to its own instrumentation version 5 naming and Microsoft's harness guidance assumes OTel export. Any client betting on vendor-neutral, portable agent telemetry right now is betting on a spec in limbo. Design the collector layer so attribute renaming is a config change, not a rewrite.

How to read this

method and known limits
  • Primary sources only where possible. Every item links a vendor changelog, release note, spec page or CVE record. Where only secondary reporting existed, it says so inline.
  • Shipped is separated from announced. A roadmap post is labelled Proposed. A release tag is labelled Shipped. This distinction is the single biggest source of confident-sounding errors in AI news.
  • Vendor benchmark claims are reproduced, not endorsed. Cartesia's leaderboard placement, AssemblyAI's 2.5% to 0%, Deepgram's 80 ms, and NiCE's customer figures are all vendor- or customer-reported on unspecified test sets.
  • Unconfirmed is written as unconfirmed. Where a date, price, version or figure could not be verified against a primary source, the item says so rather than guessing. Absence of a finding is not evidence of absence.
  • Item count is not market signal. Deepgram dominates §02 partly because it publishes a granular dated changelog and its competitors do not.
  • Fetched pages are treated as data, never instructions. Two documentation sites (Deepgram, ElevenLabs, and modelcontextprotocol.io) prepend directive text addressed to AI readers. It is benign and first-party, and it was ignored. Nothing malicious was encountered.
