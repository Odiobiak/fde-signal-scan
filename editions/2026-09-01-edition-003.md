### A2A ends its quiet period, joins the Agentic AI Foundation as a Growth Stage project
**Google / AAIF · 27 Aug 2026 · CORRECTION · COMPETITIVE · RESEARCH**
Google's Agent2Agent (A2A) protocol moved from standalone Linux Foundation hosting to formal governance under the Agentic AI Foundation (AAIF), the same foundation that has hosted MCP since December 2025. The A2A project blog states it has "officially been accepted as a Growth Stage project at the Agentic AI Foundation," describing A2A as the horizontal protocol for peer-to-peer agent collaboration, complementary to MCP's vertical agent-to-tool integration layer. No new A2A spec version shipped alongside the move; it is still v1.0.1 from May 2026.
**Why it matters:** Both prior editions of this scan recorded "A2A: nothing since May" as a source-health fact, and that line is now stale. It changes nothing technical for a Cognigy build consuming MCP tools today, but putting A2A and MCP under one governance umbrella raises the odds of future cross-protocol alignment, for example on identity and auth, that could eventually touch how Cognigy-side MCP tools interoperate with A2A-speaking agents in a multi-vendor estate. Worth a one-line correction anywhere "A2A has stalled" was said as settled fact.
*Caveat: governance change only, not a spec release. Announcement dated 17 Aug; formal acceptance post dated 27 Aug.*
Sources: https://a2a-protocol.org/latest/blog/category/announcements/ · https://www.axios.com/2026/08/17/a2a-agentic-ai-foundation-open-ai-standards

### Fable 5.1 and Mythos 5.1 ship with forced tool-choice now returning an error
**Anthropic · 1 Sep 2026 · CRIT · BREAKING · LAUNCH · SHIPPED**
Claude Fable 5.1 and Claude Mythos 5.1 (`claude-fable-5-1`) went GA on the Claude API, Bedrock, Vertex and Azure Foundry. List price is unchanged from Fable 5 at $10/$50 per MTok input/output, but cached-token reads drop from $1 to $0.25 per MTok, a 75% cut Anthropic says nets roughly 25–45% cheaper depending on how agentic the workload is. Context is a flat-priced 1M tokens, max output 128K. The breaking change: forced `tool_choice` of type `"any"` or `"tool"` now returns a 400 error, because thinking is always on for these models and a forced tool call would skip it. Migration path is `strict: true` tool use or structured outputs, and conversation history must now be treated as append-only — editing or reordering earlier turns invalidates thinking blocks.
**Why it matters:** If any Cognigy LLM node or custom intent-extraction flow relies on forced `tool_choice`, pointing the connection at `claude-fable-5-1` starts throwing 400s the moment it's selected — audit this before flipping the model dropdown on any existing build. The append-only history requirement is real friction against Cognigy's context/session-memory handling, which sometimes trims or rewrites prior turns; that pattern would silently invalidate thinking blocks or error mid voice session. The cache-read price cut is a genuine cost lever for any Cognigy flow that resends large system prompts or tool schemas turn over turn — worth re-testing cache-hit economics on high-volume deployments.
Sources: https://www.anthropic.com/claude-fable-and-mythos-5-1 · https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1

### Paired on/off trials propose a portable way to measure whether an agent skill actually helps
**NVIDIA · 20 Aug 2026 · INFO · RESEARCH · preprint**
